# ZWLY Lab — portfolio collection

The confirmed Style B remains: white, charcoal, green emphasis, fine rules,
self-hosted Archivo with Chinese system fallback. No avatars.

## Composition

The portfolio leads. Home introduces three directions through real paired
previews: interactive learning, applications/interfaces, and visual expression.
The visitor chooses which work to explore. PyScreen's task → code → feedback
walkthrough belongs inside its own detail page, with the screenshot kept intact.
Campus and JD have different phone/desktop media proportions. Algorithms are
experiments; visuals are curated series. Concepts remain quiet archives.

The site has three reading densities: visual product introduction, scannable
collection, and single-column short articles. Do not reuse one huge header and
one uniform media box for every surface. Fine rules mark real content changes.

## States and motion

140ms local feedback; 220–280ms state/series changes; one 500ms product arrival.
No automatic hero cycling. Screenshot annotations follow the selected step.
Gallery uses native modal focus/Escape behavior. Image changes progressively use
the native View Transition API; unsupported/reduced-motion browsers update
immediately. A new input interrupts a pending image transition.
All content is available without waiting for motion.

## Truth and evidence

Use actual interfaces and original collected visuals. Historical screenshots,
empty states, concepts, and unverified learning outcomes are labeled. Do not
invent role claims, business execution, conversion metrics or testimonials.
Do not substitute decorative device renders for interface evidence.

## Maintenance

Keep existing Next.js routes, data files, native controls and licensed components.
Case text lives in src/data/cases.ts. No animation/UI library is needed for the
current scope. References and source notices remain in docs/design-references.md
and licenses/. Source reuse permission does not cover external articles/media.

## Verification

Desktop and mobile renderings, keyboard/dialog restoration, live demo ready/error,
rapid image changes and reduced motion are the functional acceptance boundaries.
Real visitor desirability and real-device performance remain separate validation.
